# Seevido 浣熊小短剧

固定形象为可爱、圆润、毛茸茸的浣熊，保留最新参考的灰色毛、黑眼罩、脸型、环纹尾巴和短小比例。可按故事加入小熊猫，但 red panda 的红棕毛与浣熊明显区分。总体为精致可爱 3D 动画，不把小动物突然变成写实野兽。

## 单只与多只

人数由本次剧情决定，不能用旧版“只许一只”“最多三只”覆盖明确的三只、五只要求。多只时先建立清楚的角色表：总数、主要跟踪对象、相对位置、可识别外观差别。保留主体身份，不靠临时变色区分同一角色。

为复杂场景拆参考职责：角色全貌、起始场景、关键道具、第二地点。素材编号对应真实上传顺序；待生成图片明确列为待生成。只上传图片时，最终 prompt 不能引用案例视频。

## 故事与空间

按用户给定的剧情组织“发现 → 触发 → 追逐／争抢 → 结果 → 情绪反应”。保持可见原因：被发现后才惊慌，没抢到后才哭，得到安抚后才平静。哭声为稚嫩卡通角色声音，不自动加入解释旁白。

POV 固定为同一观察者：手从画面边缘进入，方向与镜头一致，不长出额外手，不突然变成外部航拍。追踪指定一只时明确其起始位置和后续路线，其他动物离开画面不等于消失。

复杂道具必须交代路径，例如娃娃机：控制杆 → 机械轨道 → 抓取位置 → 出口 → 地面 → 手掌。夹爪包围身体后才提起，出口尺寸容纳角色，接触与移动过程清楚。小动物和碰撞保持虚构柔软动画逻辑，不加入伤口或真实虐待画面。

15 秒多事件时分配紧凑但可读的时段；场景转移需要明确切点。减少多余停顿，不能省略用户指定的结局。确实装不下时说明压缩取舍，而非偷偷遗漏剧情。

## 输出与验收

参考图片 prompts + 素材用途表 + 中文完整视频 prompt。常用 15 秒 9:16，当前请求优先。音效、环境音、音乐与对白分别明确。品牌当前为 Seevido，不沿用旧 AIFacefy 名称；仅在要求品牌展示时加入可读品牌文字。

检查角色总数、跟踪对象、道具位置、情绪原因、POV 手数与镜头切点。已生成图片才可声称完成生图；提示词不能保证成片一致性。示例见 下方的「示例」部分。


## 示例

# 娃娃机 POV 小故事

三张待生成图：A 锁定圆润灰浣熊形象；B 锁定商场娃娃机内部、轨道、软垫与宽出口，明确六只浣熊位置，右前方一只是主跟踪对象；C 锁定同一主角被放在手掌后的体积比例。每张保持同一 3D 动画风格，画幅 9:16，无界面和水印。

```text
15秒，9:16，可爱3D动画POV小故事。@Image 1锁定浣熊外貌，@Image 2锁定娃娃机和六只浣熊的初始位置，@Image 3锁定右前方主角与人类手掌的比例。只使用这三张图片，不把角色设定背景当成场景。
0–2秒：POV右手拨动控制杆，机器里的轨道机械臂随之横移；六只小浣熊看到夹爪接近才惊慌挤动，右前方主角转身试图跑开。
2–5秒：圆钝夹爪下降，柔软地环住主角身体再提起，它的短爪扑腾、尾巴下垂，发出奶声奶气的卡通哭声。其余五只留在机器内。
5–8秒：夹爪沿轨道移到宽出口上方，张开，主角落入柔软斜槽，沿短滑道滚到外部软垫上。镜头向下跟随出口，连续追踪同一只。
8–11秒：主角站起往右跑两步，POV跟近，一只手从侧面轻轻托住腹部，另一只手在下方承接，将它捧起。没有抓住脖子或尾巴。
11–15秒：主角稳坐一只手的掌心，另一只手轻轻抚摸头顶。它先抽泣，随后眨眼放松，最后抬头安心地看向镜头。背景娃娃机与商场仍在原方向。
同一观察者连续手机POV，无外部机位；始终最多两只手。轨道声、夹爪声、软垫落地声和稚嫩哭声按事件发生，最后哭声渐弱，轻柔原创配乐收尾。数量固定，主角不换毛色、不复制，夹爪无尖锐结构，无伤口、乱码字幕和水印。
```

“六只”是此例补充，不是默认强制人数。用户给五只争甜甜圈时，角色表和最终 prompt 均改为五只，明确哪一只没抢到。
